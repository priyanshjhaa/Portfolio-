# Portfolio working requirements

- Read `revamp.md` before working on the book experience; it records the approved product and design requirements.
- Keep the book centered, with one page visible at a time on every device. Center the cover; left-align chapter text.
- Use only the warm editorial palette: oatmeal, ivory, brown charcoal, taupe, and subdued olive. No bright colors, blue, violet, indigo, neon, or colorful gradients in the portfolio UI. Preserve original screenshot colors.
- Preserve all project content, source links, photographs, and `/systems/[id]` routes. Clearly distinguish implemented work from prototypes and planned features.
- Use existing Next.js, TypeScript, `motion/react`, CSS, and local assets. No canvas, WebGL, game engine, flipbook dependency, sound, or autoplay.
- Keep chapter navigation accessible through buttons, contents links, keyboard, and optional horizontal swipes. Never intercept vertical scrolling.
- Preserve URL/history navigation, reduced motion, visible theme controls, 44px targets, readable typography, and a no-JavaScript/short-screen reading fallback.
- Use semantic server-rendered content, explicit image sizes, and lazy loading for project imagery. Preserve static export compatibility.
- Validate type checking, production build, mobile/tablet/desktop layouts, both themes, history, focus, reduced motion, and reading mode before delivery.
- Preserve unrelated work, including `artifacts/` and `scripts/`. Do not commit, push, or open a PR unless requested.
